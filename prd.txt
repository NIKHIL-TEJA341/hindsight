PRODUCT REQUIREMENTS DOCUMENT (PRD)

PROJECT: SALES & REVENUE INTELLIGENCE AGENT
TAGLINE: An AI Sales Agent That Remembers Every Deal

============================================================
1. PRODUCT OVERVIEW
============================================================

Sales & Revenue Intelligence Agent is an AI-powered sales assistant designed to help sales representatives manage prospects, deals, customer interactions, objections, requirements, and follow-ups.

The key differentiator is persistent agent memory using Hindsight.

Unlike a normal chatbot that starts with little or no knowledge in a new conversation, this agent can remember important information learned from previous sales interactions and use that information in future conversations.

The application will use:

- Streamlit — User Interface
- Python — Application development
- Agno — AI Agent framework
- Groq API — LLM provider
- GPT-OSS 120B — Primary LLM
- Hindsight — Long-term agent memory
- SQLite — Chat/conversation storage only

The project is based on the hackathon requirement to build an AI agent that can remember, recall, and improve over time using Hindsight.


============================================================
2. PROBLEM STATEMENT
============================================================

Sales representatives interact with prospects across multiple meetings, calls, emails, and follow-ups.

Important information is easily lost:

- Customer requirements
- Pain points
- Objections
- Budget
- Decision makers
- Competitors being considered
- Pricing discussions
- Previous proposals
- Promises made by the salesperson
- Previous outcomes
- Preferred communication style
- Reasons for rejecting previous proposals

A normal AI chatbot may provide a useful response based on the current conversation, but when a new conversation starts, the salesperson may need to provide the previous context again.

This creates repetitive work and prevents the AI agent from becoming more useful over time.

The proposed system solves this by giving the sales agent persistent memory through Hindsight.


============================================================
3. PRODUCT OBJECTIVE
============================================================

Build an AI sales agent that:

1. Understands sales-related conversations.
2. Helps sales representatives with deals and prospects.
3. Identifies useful information from interactions.
4. Stores important long-term information in Hindsight.
5. Recalls relevant information during future interactions.
6. Uses remembered information to generate personalized responses.
7. Works across completely new conversations.
8. Demonstrates clear improvement as more information is accumulated.

The core product principle is:

"Every interaction makes the sales agent more informed about the deal."

5. CORE USE CASE
============================================================

The central use case is:

DEAL INTELLIGENCE

The agent remembers the history and context of a sales opportunity and uses that information to assist the salesperson in future interactions.

Example:

A salesperson interacts with the agent about Acme Corporation.

The salesperson tells the agent:

"Acme is interested in our enterprise plan."

Later:

"Their CTO is mainly concerned about deployment time."

Later:

"The CFO will not approve anything above $50,000 without additional justification."

Later:

"They rejected our previous proposal because the implementation timeline was six weeks."

Hindsight retains these important pieces of information.

Several days later, the salesperson starts a completely NEW CHAT:

"Prepare me for my next Acme meeting."

The agent retrieves the relevant memories and responds using the accumulated knowledge.

The salesperson does NOT need to explain Acme again.


============================================================
6. WHY HINDSIGHT IS ESSENTIAL
============================================================

Hindsight is the central memory layer of the application.

It is NOT being added as a decorative feature.

The application should demonstrate that:

WITHOUT HINDSIGHT:

The agent does not have the long-term learned context when starting a new conversation.

WITH HINDSIGHT:

The agent recalls relevant information from previous interactions and produces a more contextual response.

Therefore, removing Hindsight should remove the application's core long-term memory capability.

This creates a clear before/after demonstration for the hackathon.


============================================================
7. IMPORTANT DISTINCTION: SQLITE VS HINDSIGHT
============================================================

SQLite and Hindsight have different responsibilities.

SQLITE:

SQLite is used only for application-level chat storage.

It stores:

- Chat ID
- Conversation title
- User ID
- Message
- Message role
- Timestamp
- Conversation metadata

SQLite allows the application to:

- Display previous chats
- Show a chat list
- Continue an existing conversation
- Reopen an old conversation
- Maintain UI-level conversation history

SQLite is NOT the agent's long-term memory.

HINDSIGHT:

Hindsight stores and recalls important information learned from interactions.

Examples:

- Customer requirements
- Customer objections
- Stakeholders
- Budget information
- Deal information
- Preferences
- Previous decisions
- Previous proposal outcomes
- Important commitments
- Relevant historical context

The agent uses Hindsight when it needs information from previous interactions.

Therefore:

SQLite = "What messages were in the conversation?"

Hindsight = "What does the agent remember and know from previous interactions?"

9. COMPLETE INPUT FLOW
============================================================

STEP 1:
User enters a sales-related message in Streamlit.

Example:

"Prepare me for my next meeting with Acme."

STEP 2:
Streamlit receives the input.

STEP 3:
The application identifies the current user and conversation.

STEP 4:
The message is sent to the Agno Sales Agent.

STEP 5:
The agent determines what the user is asking.

STEP 6:
The agent uses Hindsight to recall relevant long-term memories.

Example:

Hindsight retrieves:

- Acme's main concern
- Previous objection
- CTO preference
- Budget information
- Previous proposal outcome

STEP 7:
The agent combines:

- Current user request
- Current conversation context
- Relevant Hindsight memories
- Sales-agent instructions

STEP 8:
The combined context is sent to GPT-OSS 120B through Groq.

STEP 9:
The LLM generates the response.

STEP 10:
Agno returns the response to the application.

STEP 11:
Streamlit displays the response to the user.

STEP 12:
Important newly learned information from the interaction is retained through Hindsight.

STEP 13:
The current conversation message is stored in SQLite for the chat UI.

- Generating natural-language responses

- Preparing meeting briefs
- Drafting follow-ups
- Suggesting responses to objections
- Using remembered information appropriately


============================================================
20. HINDSIGHT RESPONSIBILITIES
============================================================

Hindsight is responsible for:

- Persistent memory
- Retaining useful information
- Recalling relevant information
- Providing historical context
- Supporting cross-conversation memory
- Helping the agent improve its responses over time

Hindsight should be treated as the agent's LONG-TERM MEMORY LAYER.


============================================================
21. SQLITE RESPONSIBILITIES
============================================================

SQLite is responsible ONLY for application chat storage.

Suggested tables:

CONVERSATIONS

- conversation_id
- user_id
- title
- created_at
- updated_at

MESSAGES

- message_id
- conversation_id
- role
- content
- timestamp

SQLite is NOT responsible for the agent's long-term memory.

The agent should not depend on SQLite to remember sales knowledge across new chats.


============================================================
22. WHAT HAPPENS IF HINDSIGHT IS REMOVED?
============================================================

WITH HINDSIGHT:

User:

"Prepare me for my Acme meeting."

Agent:

Uses previous Acme information and provides a personalized preparation.

WITHOUT HINDSIGHT:

The same new conversation starts.

The agent has no long-term learned sales context.

It should ask for information again or provide a generic response.

SQLite can still display the old chat if the user explicitly opens it, but the agent should not automatically gain the long-term memory that Hindsight provides.

This proves that Hindsight is essential to the product's core functionality.

31. FINAL PRODUCT DEFINITION
============================================================

Sales & Revenue Intelligence Agent is a Streamlit-based AI sales assistant built with Agno and GPT-OSS 120B through Groq.

Its defining capability is persistent sales memory powered by Hindsight.

The agent remembers important information about prospects, customers, deals, objections, requirements, stakeholders, pricing discussions, and previous outcomes.

When a salesperson starts a new conversation later, the agent can recall relevant information from Hindsight and use it to provide personalized assistance without requiring the salesperson to repeat the previous context.

SQLite is used only to persist and display application chat history.

Hindsight is the long-term memory layer and the core differentiator of the application.
